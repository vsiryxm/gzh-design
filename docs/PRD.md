## 1. 背景与问题

公众号编辑器不认 CSS 类、不认外部样式表、不认 `var()`，正文样式只能靠内联样式 + `<span leaf="">` 标记层层携带。这导致：

1. **手动排版成本高**：一份 3000 字的稿子，调字号、行距、段间距、引用块、列表标记，平均要 20–40 分钟，且每次改稿都要重来。
2. **排版质量不稳定**：不同文章的间距、编号、强调色容易跑偏，同一账号前后风格不一致。
3. **AI 方案不可控**：用大模型生成排版 HTML，同输入可能不同输出，偶发丢段、丢标记、编造样式；每次要等模型、要花钱、要人复核。

### 1.1 核心洞察

排版规则本身是**确定性**的。既然六套主题的结构（章节标题长什么样、列表怎么排、引用怎么套）是固定的，就没必要每次让模型重新想一遍——把它固化成模板代码，用 Markdown 做唯一输入即可。

**产品定义：把「AI 排版技能」变成「粘贴即排版」的确定性工具。**

---

## 2. 产品定位

### 2.1 一句话

Markdown 贴进去，右边立刻看到它在手机里的样子，点一下复制，粘到公众号编辑器就是排好版的效果。

### 2.2 目标用户

| 用户 | 痛点 | 本产品提供的价值 |
|---|---|---|
| 个人公众号作者（主） | 排版耗时、风格不统一 | 一次配置好主题，之后每篇 30 秒出稿 |
| 内容运营 / 小编 | 多人排版风格漂移 | 主题即规范，谁排都一样 |
| 技术写作者 | Markdown 习惯了，不想在富文本里手调 | 保留 Markdown 工作流 |

### 2.3 使用场景

- **主场景**：本地写好 Markdown → 打开工具 → 粘贴 → 选主题 → 复制 → 公众号编辑器 ⌘V → 发布。
- **次场景**：把已发布文章的 HTML 导出归档；对比六套主题挑一套定下来。
- **反场景**：需要封面图、目录卡、复杂图文混排的排版（本产品不做）。

### 2.4 目标与非目标

**目标**

- 从粘贴到可复制，主流长度文章（3000 字）≤ 1 秒。
- 复制到公众号后**样式零丢失**（在 Chrome + 公众号编辑器实测）。
- 输出符合公众号 HTML 规范（无 `div` / `class` / `id` / `position`，文本节点全部 `span leaf` 包裹）。
- 同输入同输出，任何时候重开都是同一份结果。

**非目标**

- 不做登录、不做云同步、不做多端协作。
- 不做 AI 生成正文（只做排版）。
- 不做封面卡 / 目录卡：那是给人读的固定内容，工具猜不准。
- 不做所见即所得的富文本编辑（输入侧就是 Markdown 源码）。

## 3. 信息架构与界面规格

### 3.1 整体布局

```
┌──────────────────────────────────────────────────────────────┐
│ header  [标题] [风格▸6主题]      [深/浅] [双栏/左/右] [?]      │
├───────────────────────────┬──────────────────────────────────┤
│ 左栏 pane.left            │ 右栏 pane.right                  │
│ ┌ pane-head ────────────┐ │ ┌ pane-head ───────────────────┐ │
│ │ MARKDOWN  清空 导入.md │ │ │ HTML预览 [手机|PC] 同步滚动  │ │
│ ├───────────────────────┤ │ ├──────────────────────────────┤ │
│ │                       │ │ │  stage                       │ │
│ │   textarea            │ │ │   [手机机身] 或 [PC 白卡]     │ │
│ │                       │ │ │                    (回到顶部) │ │
│ └───────────────────────┘ │ └──────────────────────────────┘ │
├───────────────────────────┴──────────────────────────────────┤
│ footer 总计/汉字/英文/标点/章节 ✓标点  [下载 HTML] [复制到公众号] │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 尺寸与阈值

| 项 | 值 | 说明 |
|---|---|---|
| 两栏默认比 | 1 : 1 | CSS Grid `var(--lw,1fr) 5px minmax(0,1fr)` |
| 分隔条宽度 | 5px | 命中区左右各外扩 4px |
| 拖拽下限 | 左栏 ≥300px | 同时保证右栏 ≥340px |
| 手机预览宽 | 375px | 真机逻辑宽度，字号观感与手机一致 |
| 手机机身高度 | `右栏可用高 × 0.99 − 24` | 24 = 上下中框高光；宽度不缩放，只伸缩高度 |
| PC 预览宽 | 677px | 桌面微信阅读宽度 |
| 预览缩放 | `min(1, 可用宽/内容宽)` | 只在空间不足时缩小，从不放大 |
| 窄屏断点 | 820px | 以下改为上下堆叠，隐藏分隔条 |
| 回到顶部阈值 | scrollTop > 320px | 显示浮动圆钮 |

### 3.3 视觉基调

- 界面深色为默认，浅色为可选；两套都只影响工具自身。
- 主色 `#059669`（摸鱼绿），与主题默认色一致。
- 界面皮肤与导出样式**完全解耦**：界面用 CSS 变量，导出用写死的内联颜色。

## 4. 功能需求

### F1 输入与解析

| 项 | 规则 |
|---|---|
| 输入方式 | 粘贴（textarea）、导入 `.md` / `.txt` 文件、自动装载示例 |
| 触发渲染 | 输入后 120ms 防抖 |
| 解析粒度 | 按行状态机：围栏代码 → 标题 → 分割线 → 引用 → 图片 → 列表 → 段落 |
| 行内标记 | 行内代码 → 链接（只留文字）→ 加粗 → 高亮 → 下划线 → 删除线 |
| 段落合并 | 连续非空行合并为同一段落（`\n` 直接拼接，不插空格） |

**验收**：`examples/fixture.md` 的 14 条语法规则全部命中；渲染结果中不含裸文本（全部 `span leaf` 包裹）。

### F2 主题渲染

六套主题，**不只是换色**：章节标题、无序列表、有序列表、引用块、小节标题、末章各有一套结构。

| 主题 key | 名称 | 章节标题 | 无序列表 | 有序列表 | 引用 | 正文 |
|---|---|---|---|---|---|---|
| `green` | 摸鱼绿 | 大数字 + PART + 竖线 | 胶囊标签 + 说明 | 圆数字 | 绿虚线圆角框 | 14px / 20px |
| `red` | 红白色系 | 红底编号块 + 英文标签 | 胶囊标签 | 圆数字 | 淡红底 + 左条 | 15px / 10px |
| `graphite` | 石墨极简 | 浅灰超大编号 + 细线 | 胶囊标签 | 圆数字 | 浅灰底 + 左条 | 15px / 10px |
| `zen` | 留白禅意 | 英文标签 + 衬线 + 短线 | 细线行 | 细线行 | 细线左竖条 | 15px / 16px |
| `ticket` | 摸鱼票据（默认） | 实心方块 + 黑描边 | 定高绿方块卡片 | 定高绿方块卡片 | 淡绿底 + 深绿条 | 14px / 20px |
| `olive` | 橄榄手记 | 墨色编号 + PART + 竖线 | 灰胶囊 + 橙点 | 橙圆数字 | 浅底 + 橙条 | 15px / 20px |

**章节编号**：`##` 自动编号 01/02/03…；末章若命中「结语 / 写在最后 / 总结 / 尾声 / 后记 / 一点想法 / 最后 / 收尾」，改用各主题的末章样式。

**英文小标签**：先取标题里的英文词，再按内置词典（DEAD END / APPROACH / SETUP / CONNECT / RESULT / THOUGHTS…）匹配，都没命中就留空，不硬凑。

**列表两层结构**：`- **标签**：说明` 会拆成「标签 + 下一行说明」；没有加粗标签的条目退化成普通段落。

**票据主题的绿方块定高**：`36×36`，用 `align-items:flex-start` + `line-height` 垂直居中，**不随段落文字变高**。

**验收**：六套主题各生成一份 HTML，`validate_gzh_html.py` 全部 0 ERROR / 0 WARNING；每个 `<p>` 的祖先里带 `padding:0` 的 `<section>` 恰好 1 个（防嵌套收窄）。

### F3 预览

| 项 | 规则 |
|---|---|
| 手机模式 | iPhone 外壳（灵动岛、侧键、home bar），屏内滚动，圆角 46px |
| PC 模式 | 无外壳白卡，677px，卡片自带滚动 |
| 切换 | 两种模式共用同一个 `#out` 节点，切换时搬移容器并恢复各自滚动位置 |
| 自适应 | 右栏拖窄 → 整机等比 `zoom` 缩小，不裁切不变形 |

**验收**：1000×900 右栏下 `zoom = 1` 且整机（含中框）占可用高 99%±0.5%；拖到 360px 宽时 `zoom < 1` 且机身完整。

### F4 栏位布局

- 三档：**双栏 / 只显示左栏 / 只显示右栏**。
- 单栏模式占满整个宽度，预览**居中**。
- 实现约束：单栏时 Grid 必须收成**单轨**（写三轨会让右栏落到 0 宽轨道上，被压到最左边）。

**验收**：三档切换后 `main` 上的 `only-left` / `only-right` 类正确；只显示右栏时预览水平居中。

### F5 同步滚动

- 默认开启，按**进度百分比**映射（左栏滚到 50%，预览也到 50%）。
- 90ms 时间锁防止两侧互相写死。
- 仅双栏模式生效；单栏时自动失效。
- 预期行为：源码与渲染结果行数不对应，长文会有可见漂移，不视为缺陷。

### F6 复制到公众号

| 步骤 | 行为 |
|---|---|
| 1 | `navigator.clipboard.write` 写入 `ClipboardItem`，同时带 `text/html` 与 `text/plain` |
| 2 | 失败 → `document.execCommand('copy')` 选中 `#out` 兜底 |
| 3 | 再失败 → 自绘弹窗提示「手动全选 ⌘A 后 ⌘C」 |
| 成功 | 按钮文案变「✓ 已复制，去公众号 ⌘V」，2.2s 后复原 |

### F7 下载 HTML

- 导出独立文件：`<!DOCTYPE html>` + 白底 + 677px 居中包裹 `#out` 内容。
- **文件名**：`公众号文章-YYYYMMDD-HHmmss.html`（本地时间，同一篇多次导出不覆盖）。
- 文档 `<title>`：取文章 `# 标题`（去掉文件名非法字符）。
- 空内容时点击 → 弹窗提示，不产出空文件。

### F8 缓存与示例

- 持久化到 `localStorage['gzh-paiban-v2']`，字段见 §5。
- 兼容旧版 `gzh-paiban-v1`（只有正文与主题），读到即迁移。
- **启动逻辑**：无缓存且编辑框为空 → 自动装载示例（示例覆盖全部 14 条语法）。
- 清空需二次确认（自绘弹窗）。

### F9 统计与自检

| 指标 | 口径 |
|---|---|
| 总计 | 汉字 + 英文词 + 标点 |
| 汉字 | `[\u3400-\u4dbf\u4e00-\u9fff]` 逐字 |
| 英文 | 连续字母串算 1 个**词**（不按字母），支持 `don't` / `you're` |
| 标点 | 半角 + 中文标点 + 全角标点 + 中英引号/破折号/省略号 |
| 章节 | `##` 数量 |
| 标点自检 | 检「中文后紧跟 `, ; ! ?`」，命中则黄色警告并给出处数 |

### F10 界面配色

- 两档：**深色（默认）/ 浅色**。
- 仅切换 `<html data-ui>` 与 CSS 变量，**不影响导出结果**。
- 选择随其他状态一起缓存；`<head>` 内有一小段脚本在首帧前打上属性，避免浅色用户刷新时闪深色。

### F11 帮助与弹窗

- 右上角 `?` → 弹窗：产品说明 + **致谢原作者**（带仓库链接）+ 微信号（可一键复制）。
- 所有 `alert` / `confirm` 一律换自绘弹窗：遮罩点击关闭、`Esc` 取消、`Enter` 触发主操作。
- 弹窗最大高 `100vh − 48px`，内容区可滚动。

### F12 回到顶部

- 右栏滚动超过 320px 后，右下角淡入 42px 圆形按钮；回到顶部自动淡出。
- 配色随预览模式：手机模式深色、PC 模式浅色。

## 5. 数据结构

```jsonc
// localStorage['gzh-paiban-v2']
{
  "md":     "string",      // 左栏 Markdown 原文
  "theme":  "ticket",      // green | red | graphite | zen | ticket | olive
  "layout": "both",        // both | left | right
  "vmode":  "phone",       // phone | pc
  "sync":   true,          // 同步滚动开关
  "lw":     null,          // 左栏宽度 px；null = 等分
  "ui":     "dark"         // dark | light
}
```

无数据库、无接口、无账号体系。换浏览器 / 换机器即换环境，不做同步。

## 9. 已知限制

1. **同步滚动只能按进度对齐**：源码行与渲染块不是一一对应，长文必然有漂移。
2. **`file://` 下剪贴板可能被拦**：需用 `npm start` 起本地服务器，或走选中的兜底路径。
3. **图片需自行上传**：正文图片引用的是原地址，粘到公众号后由微信自行抓取，抓不到就要手动替换。
4. **不做封面卡 / 目录卡**：这两类内容属人工创作，模板化收益低。
5. **窄屏（<520px）头部会堆到多行**：功能不受影响，但视觉偏挤。

## 附录 A：导出 HTML 的四条硬约束

| # | 约束 | 原因 |
|---|---|---|
| 1 | 每个文本节点包 `<span leaf="">` | 公众号靠此标记接管文本样式，漏一个整段失真 |
| 2 | 颜色写死，不用 `var()` | 公众号不解析 CSS 变量 |
| 3 | 禁用 `div` / `class` / `id` / `position` | 会被过滤且连带破坏布局，统一 `<section>` + 内联样式 |
| 4 | 每个块 `<section>` 成对闭合 | 漏闭合会让后续块成为子节点，`padding` 累加导致正文越往下越窄 |
